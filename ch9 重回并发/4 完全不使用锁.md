## 5. 保护可变数据

在极少数几个地方，xv6 完全**不使用锁**来共享可变数据 。

其中之一是在自旋锁的实现中，尽管人们可以认为 RISC-V 的原子指令依赖于在硬件中实现的锁。

另一个是 `main.c` (kernel/main.c:7) 中的 `started` 变量，用于防止其他 CPU 在 CPU 0 完成 xv6 初始化之前运行 ；`volatile` 关键字确保编译器切实地生成了加载和存储指令 。

第三个例子是在 `proc.c` 中对 `p->parent` 的一些使用 (kernel/proc.c:398) (kernel/proc.c:306)，在这些地方进行适当的加锁会导致死锁，但情况似乎很明朗：没有其他进程可以同时修改 `p->parent` 。

第四个例子是 `p->killed`，它是在持有 `p->lock` 的情况下被设置的 (kernel/proc.c:611)，但在没有持有锁的情况下被检查 (kernel/trap.c:56) 。

Xv6 包含一些情况：一个 CPU 或线程写入某些数据，而另一个 CPU 或线程读取这些数据，但没有专门致力于保护这些数据的特定锁 。例如，在 `fork` 中，父进程写入子进程的用户内存页面，而子进程（可能是不同 CPU 上的不同线程）读取这些页面 ；没有任何锁显式地保护这些页面。这不严格算作一个加锁问题，因为子进程直到父进程完成写入后才会开始执行 。这是一个潜在的内存排序问题（参见第 6 章），因为如果没有内存屏障，就没有理由期望一个 CPU 能够看到另一个 CPU 的写入 。但是，由于父进程释放锁，并且子进程在启动时获取锁，`acquire` 和 `release` 中的内存屏障确保了子进程的 CPU 能够看到父进程的写入操作 。
